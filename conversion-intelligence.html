The problem

An ecommerce team wants to understand which browsing patterns are associated with purchase. Class imbalance and potentially leaky features can make a model look better than it really is.

The decision: Design a prospective test before using scores for interventions.

What I built

Two trained classifiers, a later-month holdout, feature-importance analysis, and an interactive threshold explorer.

Public sourceValidate & prepareAnalyze & testExplore & decide

What the evidence says

0.337 average precision on unseen months

Compared with a 0.207 constant-score baseline, on 4,725 sessions. ROC AUC is 0.708.

The useful story is the trade-off

At the validation-locked threshold (0.227), held-out precision is 35.9% and recall is 34.0%. Most flagged sessions still do not purchase.

A better question for the next experiment

Can a helpful intervention create incremental purchases without harming customer experience? Prediction alone cannot answer that. Test a defined intervention prospectively with a randomized control group.

How it works

  1. Retain all 12,330 sessions. UCI describes one user per session; identical feature rows are therefore retained rather than assumed to be duplicate users.
  2. Exclude PageValues because its relationship with transaction value presents leakage risk. Use Month only to define splits. Engagement features make this a retrospective session analysis.
  3. Train on observed months before October, choose between logistic regression and random forest on October average precision, and hold out November–December.
  4. Set a score threshold at the 80th percentile of October validation scores. Refit the selected model on pre-test months and evaluate that threshold unchanged on the holdout.
  5. Report ranking quality, calibration error, precision, recall, and shuffled-feature importance. The dashboard allows exploratory threshold comparisons.

Limits & next steps

Session totals and exit metrics may only be complete after a visit ends. This is not a deployable early-session targeting model. Raw event timestamps are unavailable, and month-level ordering cannot establish exact event chronology.

Holiday-season shift, class imbalance, uncalibrated probabilities, and modest precision limit operational use. No causal lift, revenue gain, or saved marketing cost is claimed. The threshold slider explores held-out outcomes; tuning on it would require a new holdout.

Next: collect point-in-time event features, calibrate on a separate validation period, monitor drift, and run a controlled intervention. Source: Sakar & Kastro (2018), UCI Online Shoppers, CC BY 4.0.
